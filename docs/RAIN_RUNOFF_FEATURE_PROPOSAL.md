# 雨天時の地表浅水生成・実質流下循環案

本ドキュメントでは、降雨中に地表へ低水位の水を生成し、既存の流体システム上で**実際に流れ・溜まり・水位を押し上げる**循環挙動を持たせる追加機能案を整理します。見た目の賑やかしではなく、川へ合流したり窪地で池化して水位を変動させる実用効果を重視します。既存の雨補充 (`rainRefillChance`, `rainFillsWaterHigherV2`) と両立しつつ、プレイヤー体験とワールド安定性を壊さない範囲での実装可否、オン/オフ制御、拡張アイデアをまとめています。

## 目的
- 雨滴由来の流量を実際の水ブロックとして生成し、川・谷・洞窟へ流下させて水位変動を生む。
- 窪地や地形の窪みに水が滞留し、小さな池・湿地化を引き起こすことで、雨天後も短時間の水位上昇が続く状態を再現する。
- 既存の水量均し・蒸発・バイオーム補充ロジックと競合しないよう、段階的に導入できる設計を用意する。

## 想定する基本挙動（正常系）
1. 雨が降っている地表（天空判定が通る空気ブロック上）に、設定した最大水位の「浅い流体ブロック」をランダムに生成する。傾斜がなく平地でも生成を許可する（平地は後続の拡散でわずかに広がる）。
2. 生成された浅い水は通常の流体更新に乗り、傾斜方向へ流下しつつ**隣接する水と合流して合計水位を増やす**。浅水は BFS（`EnhancedFluidBFS` など）での優先度を低く設定し、既存フローを圧迫しない。合流によってレベルが上がった場合、既存の流体アルゴリズムに従って追加の流動や拡散が発生する。
3. 谷や窪地など流出先のない場所では水が滞留し、周囲の浅水が集まることで**一時的な池や湿地化**が起こり、バニラ水源の高さに漸近する。溢水時は低い側へ流出し河川へ合流する。蒸発が無効化される夜間であれば池はそのまま残留してよい。冠水は最大 4 ブロックの高さまで許容し、それ以上は抑制する（安全弁）。
4. 地表で溜まった水が洞窟や隙間に接している場合、既存の流体更新で地下に流れ落ちて**帯水層を増水**させる。`rainFillsWaterHigherV2` が有効なら、上昇した水位がさらに補充を受けやすい。
5. `rainRefillChance` や `oceanRiverSwampRefillChance` のような既存の雨補充処理がある場合、それらの後に本機能が走る。補充で増えた水位と合流し、河川・海洋の水面を緩やかに押し上げる。河川や「無限水面」扱いのバイオームでは、上昇を完全に遮断せず安全幅を持って許容する。河川では堤内水位がしきい値を超えた場合、低い岸側へあふれ出す「決壊」挙動を発生させ、自然な氾濫と排水を演出する。
6. ランダムイベントとして、合流時に水位が一段高く生成される「局所的な水位ジャンプ」を低確率で発生させ、短時間の冠水や増水を演出する（上限は別途設定でキャップ）。
7. シールドされた室内、ネザーなど雨が届かないディメンションでは生成しない。
8. 砂利・草・土など吸水性の高いブロックでは生成確率を抑え、氷・ソウルサンドなど特殊ブロック上では生成しない（安全側のデフォルト）。

## 入力・出力・制約
- **入力条件**: `Level#isRainingAt(pos)` か同等の天候 API で雨を確認できること。空気・水・非固体ブロック上に限る。
- **出力**: 低水位の流体ブロック生成（`FluidState` でレベル指定）。生成後の水位合成・流動は既存の流体更新に委譲する。
- **制約**:
  - チャンク更新負荷を抑えるため、1 チャンクあたりの試行回数を制限（例: ランダムティックに上限 N）。
  - 既存の `FluidTickBuffer` / `EnhancedFluidBFS` のワークロードを圧迫しないよう、水位を小さく保つ。ただし合流・滞留による水位上昇はバニラの水位計算を尊重する。浅水は BFS 優先度を 1 段階落とし、既存の水源処理を先に捌く。
  - マルチプレイでの同期: 新規パケットを増やさず、既存の流体同期に乗せる（通常の水生成扱い）。
  - 川・湖・海に接するチャンクでは生成頻度の動的クランプを入れつつ、上限を緩めて「無限水面」がゆるやかに上昇する余地を残す。
  - 蒸発は昼間（または非夜間）に限定し、夜間は水たまり・冠水をそのまま残留させる。

## オン/オフと調整用の新規設定案
`FFConfig` に以下のフィールドを追加する想定（デフォルトは保守的に無効）。名前は英語で揃える:
- `enableRainRunoff` (boolean, default: `false`): 機能のグローバルトグル。
- `rainRunoffMaxLevel` (int, default: `2`): 生成する浅水の最大レベル（1=最も浅い）。合流で上昇する場合もこのレベルが初期値になる。
- `rainRunoffSpawnChance` (float, default: `0.05f`): 1 チャンク 1 試行あたりの生成確率。環境負荷に応じて調整。
- `rainRunoffMaxAttemptsPerChunk` (int, default: `2`): 1 チャンク内で探索する最大ブロック数。
- `rainRunoffSlopeSearchRange` (int, default: `4`): 傾斜を探す水平距離。`ChunkLocalSlopeCache` と同等かそれ以下を推奨。
- `rainRunoffPoolingDepthCap` (int, default: `4`): 池化・滞留で到達を許容する最大水位（バニラ水源レベルは 7）。冠水は 4 ブロック高さまで許容し、それ以上はクランプする安全弁。
- `rainRunoffRiverMergeLimiter` (float, default: `1.0f`): 河川・湖面に接する際の増水係数。1.0 でバニラ水源相当、0.5 で半減、2.0で倍増。
- `rainRunoffBiomeMultiplier` (map/プリセット): 河川/海洋では倍率 2.0、砂漠では 0.3 など、バイオーム別に発生量を調整。
- `rainRunoffDryBlockDampening` (float, default: `0.5f`): 草・砂利・土など吸水しやすいブロック上での確率減衰係数。
- `rainRunoffCaveLeakChance` (float, default: `0.1f`): 窪地から下層へ水が抜ける（漏斗状）場合の発生確率。地下水路形成を抑制・許容するノブ。
- `rainRunoffRandomLevelJumpChance` (float, default: `0.02f`): 合流・生成時に 1 レベルだけ高い水位を置く低確率イベント。局所的な冠水や水面上昇を演出する。
- `rainRunoffInfiniteWaterAllowance` (float, default: `0.25f`): 川・海など無限水面で許容する最大上昇幅（レベル換算）。0 で上昇を抑止、0.25 なら 1/4 レベル分の上昇を許容。
- `rainRunoffFloodingSoftCap` (int, default: `5`): 周辺ブロックの平均水位がこの値を超えると新規生成確率を自動減衰させ、冠水を緩やかに抑える。
- `rainRunoffDaytimeEvaporationOnly` (boolean, default: `true`): 蒸発処理を昼間（もしくは非夜間）に限定する。夜間は池や冠水が残留する。
- `rainRunoffRiverOverflowThreshold` (float, default: `0.75f`): 河川・湖面が 75% の水位（例: レベル 6/8 相当）を超えた際に、決壊候補としてチェックを開始するしきい値。
- `rainRunoffBreachOutflowFactor` (float, default: `1.5f`): 決壊発生時に低地へ流す流量倍率。1.0 で通常流量、1.5 で 1.5 倍の勢いで周囲へ拡散する。

## 正常系フロー（ステップ）
1. サーバー側雨チェック → トグル `enableRainRunoff` が false なら即終了。
2. ランダムティックや雨専用フックで、チャンク内のランダム座標を最大試行回数分ピック。傾斜が無くても生成候補とする。
3. 地表判定（天空 + 固体ブロック上 + 空気/水/植物ブロック）を通過したら、傾斜方向を近傍探索し、見つからなくても平地生成を許可する。
4. `rainRunoffSpawnChance` を用いて水をレベル `1..rainRunoffMaxLevel` で生成。`rainRunoffRandomLevelJumpChance` が発火した場合は 1 レベル増しで生成する。流動先が低地・谷・河川・洞窟に接している場合は `rainRunoffRiverMergeLimiter` や `rainRunoffInfiniteWaterAllowance` を考慮して水位を計算。
5. 生成した水は通常の流体ロジックへ委譲し、合流・滞留で水位が上がった際も `rainRunoffPoolingDepthCap` を上限としてクランプしつつ、`FluidTickBuffer` によるスケジューリングと相互作用する。`rainRunoffFloodingSoftCap` を超える局所水位では新規生成を減衰させ、冠水を滑らかに収束させる。河川水面が `rainRunoffRiverOverflowThreshold` を超えて上昇した場合、低い岸や開口部へ優先的に流出し、`rainRunoffBreachOutflowFactor` を掛けた勢いで周囲へ拡散する。
6. 滞留箇所で `rainRunoffCaveLeakChance` が発火すると、下層へ流出して地下水を増やし、周囲の水位を下げる。
7. 日中（`rainRunoffDaytimeEvaporationOnly=true` の場合）に限り既存蒸発ロジックで浅水・水たまりを徐々に減衰させる。夜間は蒸発しないため、池や冠水がそのまま残り、朝になったら再開する。
8. `rainRefillChance` やバイオーム補充が同 tick で発火した場合も、流体側の上限チェックで水位が上がり過ぎないように制限。

## 異常系・安全策
- 傾斜が見つからない場合でも生成は可能だが、`rainRunoffSpawnChance` に従うため過剰生成は起きにくい。
- 暴走防止のため、1 tick あたりの生成数をグローバルでクランプ（例: サーバー全体で 64 個まで）。
- 水の流下先が黒曜石やネザーラックなど特殊ブロックの場合はバニラ挙動を尊重し、特殊ケースは既存ロジックに委譲。
- 池化で `rainRunoffPoolingDepthCap` を超えそうな場合は、新規生成を抑制しつつ既存水の流出を優先する。
- マルチプレイで水面が段階的に上昇する際の同期遅延を避けるため、クライアント側に水位差分のみを送る（既存フレームでの再送を利用）。

## テスト観点
- 雨天時に草原で浅い水が生成し、雨が止むと日中に蒸発・流下で自然に減り、夜間は蒸発が止まること。
- 砂漠・ネザーなど雨が届かない場所では生成しないこと。
- 流入先が谷・川の場合に実際に水位が上昇し、池化が `rainRunoffPoolingDepthCap` の上限内で安定すること。夜間に池が残り続け、朝に蒸発が再開すること。冠水が 4 ブロック高さまで許容され、それ以上は抑制されること。
- `rainFillsWaterHigherV2=true` と併用しても水位が過度に増えないこと。
- `rainRunoffInfiniteWaterAllowance` を有効にした場合、河川や海でゆるやかな水位上昇が許容されること。
- `rainRunoffRandomLevelJumpChance` により局所的な水位ジャンプが起こり、一時的な冠水や増水が発生すること。
- 河川で水位がしきい値を超えた際に、決壊・氾濫が発生し、低地へ向けて溢れ出す流路が形成されること。
- `enableRainRunoff=false` で従来挙動に完全一致すること（回帰テスト）。
- マルチプレイ環境でクライアントとサーバーの水位が同期し続けること。
- `rainRunoffCaveLeakChance` を高くした場合に、地下空洞へ水が流れ込みつつサーバー TPS が安定すること。

## 将来の拡張アイデア
- **水たまりの成長**: 近接した浅水が合流すると一時的にレベルを上げ、蒸発タイマーが延びる演出。
- **汚れ・透明度の変化**: 草地・泥・ソウルサンド上では水の色やパーティクルを変えて視覚差分を出す。
- **風・地形依存の流量補正**: バイオームや高度差によって `rainRunoffSpawnChance` に補正を掛け、山岳で流量増、樹海で減少。
- **ゲームルール連動**: `doWeatherCycle` や独自ゲームルールと連動し、イベントベースでオン/オフを切り替え可能にする。
- **性能ガードの自動調整**: TPS が低下した際に発生頻度を自動で減衰させるフェイルセーフ。

## 非目標（今回扱わないもの）
- 雨粒ごとのパーティクル大量生成や特殊レンダラー（パフォーマンスコストが大きいため別検討）。
- 新規フルイドタイプの追加（バニラ水を利用する前提）。
- バイオームごとの詳細な音響・視覚エフェクト（将来の装飾要素として分離）。
