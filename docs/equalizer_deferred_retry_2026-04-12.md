# Equalizer Deferred Retry 2026-04-12

## 原因

- `ParallelFluidEqualizer.flush(...)` は tick ごとにキュー全体を取り出して処理していた。
- その中で surge 直後として保留した候補は、代表点選別の段階で `continue` されるだけで、次 tick 用のキューへ戻されていなかった。
- そのため「一度流れて水位は動いたが、その後の平均化だけ起きない」状態が残りやすかった。

## 再発条件

- 流入直後の水が同 tick 中に equalizer 候補へ入る。
- その tick は `flowActive` / momentum / touched chunk 判定で保留される。
- 次 tick 以降に再キューされず、その接続領域の均しがそこで止まる。

## 修正

- surge 直後で見送る候補は破棄せず、次 tick の equalizer キューへ戻すようにした。
- これで初動の過剰な BFS だけ避けつつ、静かになった後の再平均化は継続できる。

## 今後の方針

- 「今回はまだ早い」判定を入れるときは、破棄か延期かを分けて考える。
- fluid の接続性や均し処理では、1 tick 遅らせても良い候補を失わないことを優先する。
