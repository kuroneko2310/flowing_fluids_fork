# 均等化ロジック改良のためのアイデア

Flowing Fluids の現行実装では `AdaptiveTickScheduler.shouldRunBFS` の安定判定と、`EnhancedFluidBFS.performEqualization` の勾配重み付け探索がボトルネックになり、時間が経っても水平面での平均化や離れた高水位の処理が進まないケースがあります。以下は、既存の仕組みを活かしつつ追加できる改良案です。

## 1. タイムベースの再評価トリガー
- **狙い**: 安定と判定されて BFS が走らない地点でも、一定時間ごとに軽量チェックを入れて平均化を再開する。
- **実装イメージ**:
  - `AdaptiveTickScheduler` の `FluidStabilityData` に「安定継続時間」を持たせ、`EQUILIBRIUM_STABLE_THRESHOLD` を下回る状態が長時間続いた場合に、次回 tick で `shouldRunBFS` を強制 true にするフラグを立てる。
  - 強制再評価時は `EnhancedFluidBFS` に低コストモード（例: `maxDepth` と `maxNodes` を 30% に圧縮したサンプリング探索）を渡し、地形更新の有無だけ確認する。
  - その後に不安定が検知されたら通常の BFS へ移行し、安定が続く場合は強制フラグをリセットする。雨生成や流入検知 (`notifyFluidChange`) と併用して「長時間静止した水柱でも時々ほぐす」挙動を得る。

## 2. 水平探索の補強パス
- **狙い**: 勾配重み付けが強く働く環境でも、水平面の迂回路やわずかな高低差を丁寧に踏査する。
- **実装イメージ**:
  - `getWeightedDirections` の結果をそのまま使いつつ、キューが空になる直前に「水平専用ミニ BFS」を挟む。`Direction.Plane.HORIZONTAL` のみを対象に、`visited` セットを共有しつつ 1〜2 chunk 相当の距離を追加で探索する。
  - 上記パスではモーメント予算を消費せず、代わりに簡易な「平面距離しきい値」を超えたら終了させる。これにより垂直優先の本探索を崩さず、水平の取りこぼしだけ補完できる。
  - または、勾配ベクトルが 0 に近い（平坦）場合は方向キャッシュに「水平優先版」を混ぜ、`DEFAULT_DIRECTIONS` を水平起点に入れ替えるだけでも効果が出る。

## 3. 連続接触ネットワークを使った高水位のデフュージョン
- **狙い**: 遠くで繋がった高水位列が「島」のように残るケースで、接触する水路をたどって高所の水位を削り、周囲の低水位に分配する。
- **実装イメージ**:
  - `performEqualization` の後段に「連続接触クラスタ収集」を追加。`equalizedPositions` のうち、現在水位が高いノードを起点に BFS を行い、**同一流体が隣接（上下左右）で連続している範囲**を 1 クラスタとして束ねる。
  - クラスタ内で `maxHeight` と `minHeight` を取得し、`maxHeight - minHeight` が設定しきい値を超える場合にだけ拡散フェーズに入る。
  - 拡散フェーズでは、`maxHeight` 付近のノードから `minHeight` 側へ「供給枠」を作り、1 tick あたりの移送量を `BFS` の `maxNodes` に比例させて制限する。`FluidSpatialGrid` の更新後に `AdaptiveTickScheduler.notifyFluidChange` を呼び、次 tick で周囲の均等化が再開されるようにする。
  - これにより、離れた場所で高水位が鎮座している場合でも、接触水路を通じて徐々に高さを均す動きを再現できる。

## 4. 負荷と後方互換への配慮
- すべての処理は「軽量モード」を併設し、オプションやコンフィグで有効化できるようにする。特にタイムベース再評価と水平補強パスは負荷が読みにくいため、デフォルト OFF を想定。
- クラスタ拡散は `maxNodes` に比例した移送上限を設け、`processingPositions` での重複チェックを尊重して既存の排他制御を壊さない。
- 既存の均等化バランスを大きく変えないよう、デフュージョンは「高さ差が大きい場合だけ段階的に行う」設定にし、段差や滝の挙動は従来通り保持する。
